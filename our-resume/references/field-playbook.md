# 应用统计 / 统计学岗位图谱

师门主要方向是应用统计与统计学（含金融统计）。下面按**招聘方真实考察的东西**分方向，给出主线能力、条目模板、常见误写与面试追问。

示例句里的 `…` 一律是占位，必须换成用户真实事实。示例句本身**不是**用户经历，不能直接抄进简历。

---

## 1. 数据分析 / 商业分析（互联网、电商、零售、平台）

- **核心考察**：能不能把模糊业务问题拆成可计算的指标，并给出可执行结论。
- **主线能力**：问题拆解 → 指标与口径 → 数据提取（SQL）→ 分析方法 → 结论与建议。
- **条目模板**
  - **指标拆解：** 把「用户流失」拆成新增质量、活跃频次、核心功能使用三个可测维度，定义 9 项指标的分子分母与观察窗口。
  - **验证与归因：** 用分组对比 + 相关性检验筛掉 3 个伪相关因素，定位流失集中在首次使用第 2 天。
  - **结论交付：** 输出 3 条可执行建议（新手引导、召回时机、券面额），按预期影响排序，供运营排期。
- **常见误写**：工具清单代替分析（"使用 Python、SQL、Excel 完成分析"）；只写数据规模不写结论；把数据集名字当业务场景。
- **面试追问**：这个指标的分子分母怎么定？为什么不看另一个指标？如果样本偏了怎么办？

## 2. 风控建模 / 信用评分（银行、消金、互金）

- **核心考察**：建模是否可解释、变量是否合规、指标是否达到业务可用线。
- **主线能力**：样本与好坏定义 → 变量筛选（IV/WOE）→ 模型与验证（KS、AUC、PSI、跨期）→ 阈值与策略。
- **条目模板**
  - **样本定义：** 明确表现期与好坏客户口径，处理 3 类样本偏差（申请、放款、表现）。
  - **模型开发：** 用逻辑回归保证可解释性，从 200+ 变量筛至 30 个入模变量，训练集 AUC 0.7X、测试集 0.7Y。
  - **稳定性监控：** 用 PSI 检验跨期稳定性，定位 2 个漂移变量并说明处理方式。
- **常见误写**：只写算法名不写可解释性理由；把竞赛指标（AUC）直接当业务收益；不区分训练/测试/跨期。
- **面试追问**：为什么不选 XGBoost？WOE 的作用是什么？PSI 超过多少要处理？拒绝推断怎么做？
- 银行方向附注：逻辑回归 + 可解释性是主流，技术环境偏保守；同时准备**表达能力**与业务流程理解（详见 [投放与双轨](delivery-and-tracker.md)）。

## 3. BI / 报表体系 / 数据开发（含银行科技）

- **核心考察**：数据从哪来、口径怎么定、下游谁在用、出问题怎么查。
- **主线能力**：数据来源与链路 → 清洗与校验规则 → 口径文档 → 报表/看板交付 → 使用反馈。
- **条目模板**
  - **口径治理：** 梳理 4 张源表的口径差异，输出字段字典与 12 条校验规则（非空、唯一、跨表一致）。
  - **看板交付：** 用 Tableau 搭建 3 层看板（总览/归因/明细），支持业务按周自查，替代原有的人工汇总。
  - **质量兜底：** 增加数据量级与关键指标的异常告警，把问题发现提前到产出前。
- **常见误写**：只堆工具名（Hive、Spark、Kettle）；把"做了一张报表"当成果，不写谁在用、替代了什么。
- **面试追问**：这张表的主键是什么？指标口径变更怎么通知下游？数据延迟怎么处理？

## 4. 业务算法 / 策略算法（推荐、营销响应、定价）

- **核心考察**：业务感知力 + 用简单模型解决业务问题的能力，不是刷指标。
- **主线能力**：业务目标转指标 → 基线 → 模型选择与验证 → 上线方式与评估。
- **条目模板**
  - **问题转化：** 把「提升营销转化」转成响应概率排序问题，确定评估指标与成本约束。
  - **基线与迭代：** 以历史规则为基线（响应率 x%），比较逻辑回归与树模型的增益与可解释性。
  - **策略落地：** 按预测概率分层匹配不同成本的触达渠道，输出分层规则与预估成本。
- **常见误写**：写成研究岗口吻（追求 SOTA）；不提基线；把离线指标写成线上收益。
- **面试追问**：为什么不上深度学习？线上怎么评估？样本不均衡怎么处理？

## 5. AI 产品 / AI 交付与部署（新兴方向）

- **核心考察**：能不能把模型能力变成别人用得上的东西，以及能不能面向客户交付。
- **主线能力**：真实使用者与场景 → 原流程瓶颈 → 模型与工作流分工 → 评估方式 → 交付状态。
- **条目模板**
  - **场景定义：** 面向 XX 流程的人工整理环节，明确输入（非结构化文档）、输出（结构化表）与验收标准。
  - **工作流设计：** 用「模型抽取 + 规则校验 + 人工复核」三段式，明确模型不负责什么。
  - **评估与交付：** 用固定测试集统计抽取正确率与人工修订量，记录提示词版本与失败样例。
- **常见误写**：只会用工具就写"熟悉 Agent 架构"；把调 API 写成训练模型；不写评估。
- **面试追问**：你怎么知道它好用？失败样例有多少？换模型会怎样？成本怎么算？
- 这条线很适合统计背景：**评估设计、抽样与显著性判断**正是统计的主场。

## 6. 市场研究 / 用户研究（调研类）

- **核心考察**：问卷与抽样设计是否站得住，结论是否可推广。
- **主线能力**：研究设计 → 抽样与样本量 → 施测与质控 → 分析（交叉、显著性）→ 结论与建议。
- **条目模板**
  - **抽样设计：** 按分层抽样确定 400 份样本量与配额，控制性别/城市层级偏差。
  - **质控：** 设计 5 条逻辑校验与注意力检测题，剔除无效问卷 X%。
  - **分析：** 用交叉表 + 卡方检验比较群体差异，输出 3 条产品改进建议。
- **常见误写**：只写"发放问卷 500 份"；不写抽样方式；把描述统计当结论。
- **面试追问**：样本能代表总体吗？显著性怎么判断的？开放题怎么编码？

## 7. 政府公共统计 / 数据要素（政策蓝海）

- **核心考察**：统计制度、口径规范、数据质量与合规意识。
- **主线能力**：统计口径与制度 → 数据采集与审核 → 质量评估 → 分析报告/决策支持。
- **条目模板**
  - **制度对齐：** 按现行统计口径整理指标定义，标注与业务口径的差异与换算方式。
  - **质量审核：** 建立平衡关系与异常值审核规则，定位并修正 X 条异常记录。
  - **分析报告：** 输出结构化分析（现状、结构、问题和建议），供汇报使用。
- **常见误写**：把课题报告当政务材料；不提合规与保密；指标名称与官方口径不一致。
- **面试追问**：指标口径依据哪份制度？异常值怎么判定？数据涉密怎么处理？

## 8. 生物医药 / 临床统计（SAS 统计编程）

- **核心考察**：统计分析计划（SAP）执行、可重复性与规范文档。
- **主线能力**：方案与终点 → 数据集构建 → 统计方法与敏感性分析 → 表格与文档。
- **条目模板**
  - **数据集构建：** 按分析集定义（ITT/PP）整理衍生变量与缺失处理规则。
  - **分析执行：** 用 SAS/R 完成主要终点与亚组分析，输出 TFL 表格并核对。
- **常见误写**：只写"用 SAS 做分析"；不写分析集与缺失处理。
- **面试追问**：缺失值怎么处理？多重比较怎么控制？如何保证可重复？

## 跨方向通用规则

1. **一个项目只证一种主能力**，两个项目证明不同的能力；不要每条都写"数据清洗 + 建模 + 可视化 + 报告"。
2. **技能栏写成「工具 + 能完成的任务 + 支撑经历」**：`Python（pandas/statsmodels）：完成数据清洗与回归诊断，见项目一`。
3. 统计基础课（概率论、数理统计、回归分析、抽样、多元统计、时间序列、机器学习）写在教育背景的**核心课程**里，只在相关时列出 3–5 门。
4. **方法论优势要显性写出来**：样本代表性、显著性、置信区间、因果识别（DID/PSM）、稳健性检验——这些是统计背景相对计算机背景的差异化，别只写工具。
5. 面向银行/国企时，稳定性与合规意识可以写进技能与项目（口径、审核、留痕、保密），这是加分项。
