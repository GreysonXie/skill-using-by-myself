# JD 拆解、五维打分与证据矩阵

投简历前先花 10 分钟做这件事：判断这一岗值不值得为它重写简历，并把 JD 的黑话翻译成你的证据。本文件给的是判定标准，不是希望多投。

## 一、三道硬门槛（先过关，再打分）

任何一道不过，就不要改简历、不要投，直接记录原因。过关失败不是失败，是省下的时间。

| 门槛 | 检查什么 | 常见于统计/应用统计岗位 |
| --- | --- | --- |
| **资格门槛** | 毕业年份与应届身份、学历层次、专业目录、执业/证书硬要求、政治面貌 | 「2027 届毕业生」「硕士研究生及以上」「统计学、应用统计、数学类专业」「需已通过 CPA 两门」「中共党员优先」 |
| **语言门槛** | JD 要求的外语水平 vs 你的真实水平（CET-6 / 雅思 / 能读英文论文≠能英文面试） | 外资银行、跨境支付、海外业务分析岗 |
| **到岗门槛** | 城市、每周出勤天数、最短实习时长、能否 3 个月内到岗 | 「每周 5 天，连续 6 个月」「base 深圳，需长期驻场」 |

判定规则：
- 明确不符（专业不在目录、毕业年份不符、要求已持证）→ **不通过**，向用户引用 JD 原文。
- 表述模糊（"研究生优先""尽快到岗"）→ **有条件通过**，在投递记录里标注条件。
- 用户可能知道自己满足但你不知道（学籍状态、能否提前到岗）→ 直接问用户，不要替他判断。

## 二、五维打分（每维 0–5 分）

打分只看 JD 与用户材料的对照，不掺"我很想进去"。

| 维度 | 5 分的标准 | 数据来源 |
| --- | --- | --- |
| **D1 准入匹配** | 学历、专业、毕业时间、证书全部满足，且无隐性门槛 | JD 准入段 + 用户事实底稿 |
| **D2 技能覆盖** | JD 列出的关键技术/工具，简历能落到 70% 以上，且每项都有经历支撑 | JD 关键词表 + 简历技能栏与项目 |
| **D3 经历相关** | 至少有 1 段经历处理的是**同类问题**（同业务场景，或同方法链路） | 项目/实习的性质，与 JD 职责比对 |
| **D4 成果可证** | 至少 1 条可核实的产出或指标（口径、对照、交付物、被采纳） | 项目材料、看板、报告、上线/结题 |
| **D5 差异化** | 有一项别人不容易复制的证据（数据源、行业知识、复合技能、专利、竞赛名次） | 用户独有材料 |

**投递决策**：

- 合计 ≥ 20（均值 ≥ 4.0）：**精准投递版**。值得为它重写主线、调整模块顺序、定制加粗。
- 15–19：**精准投递版或通用版补一句定位**。可投，但只改与 D2、D3 相关的 3–5 条。
- 11–14：**海投通用版**投出去，不重写。缺的是证据，不是措辞。
- ≤ 10：不投，或作为练手。把缺口写进"下一步补什么"。

任何一维 ≤ 2 时，即使总分够也要说明：短板会在面试哪一步暴露。

## 三、证据矩阵（`要求 → 证据 → 位置 → 缺口`）

每次定制都先填这张表，再动笔。表填不出来说明这岗暂时不该投。

| JD 要求（原词） | 我的证据（事实） | 拟放模块 / 位置 | 缺口或处理 |
| --- | --- | --- | --- |
| 指标体系设计 | 与导师设计 3 类企业指标与计算口径，核对中间表 | 项目一 第 1–2 条 | 缺一次指标修改前后的对照 |
| SQL 多表查询 | 只有单表 SELECT 经验 | 技能栏写"SQL 基础查询" | 缺口：不写 JOIN/窗口函数 |
| 逻辑回归 / 风控建模 | 课程项目做过违约预测，AUC 0.78 | 项目二 第 1 条 | 可补：变量筛选过程 |
| 跨部门沟通 | 地勘项目任组长，拆 4 个环节分工 | 项目三 第 1 条 | 可补：一次冲突协调的具体做法 |
| 数据敏感度（隐性） | 发现 AUC < 0.5 的异常并定位到标签错位 | 项目二 第 3 条 | 强证据，需在简历中显性写出 |

写作要求：
- 「JD 要求」列**抄 JD 原词**，不要翻译成自己的话，否则关键词覆盖会漏。
- 「证据」列只写事实，不写评价；不能填"比较熟悉""有一定了解"。
- 「缺口」列进修改说明，**不进正式简历**。

## 四、隐性能力词典

JD 里最难的部分是形容词。下面是把中文 JD 黑话翻成可写证据的对照表，专用于统计/数据类岗位。

| JD 常见表述 | 实际考的能力 | 简历里要出现的证据形态 |
| --- | --- | --- |
| 业务敏感度 / 商业敏感度 | 能从数据看出业务含义 | 一条"发现异常 → 判断原因 → 影响什么决策"的记录 |
| 数据敏感度 | 能识别异常指标、判断数据能否支撑结论 | AUC/KS/PSI 异常、标签错位、口径不一致的定位过程 |
| 指标口径设计 | 会定义指标而不是取数 | 指标定义 + 分子分母 + 时间口径 + 核对方式 |
| 推动落地 / 跨部门协同 | 能让别人配合完成 | 协作对象（业务/产品/工程）、你推动了什么、结果如何 |
| 学习能力强 | 短时间掌握新工具并用于产出 | 新方法首次使用的具体场景与结果，不写"自学了 XX" |
| 抗压能力 | 还能保证质量 | 在截止期/多次返工下交付的具体事实，如"3 天内返工 2 版并对齐口径" |
| 用户视角 / 共情 | 能站在使用者角度定义问题 | 访谈、需求来源、使用者是谁、用完改变了什么 |
| 逻辑清晰 | 表达有因果链 | 每条经历都是"因为 → 所以"的结构，不是并列清单 |
| 数据驱动决策 | 用测试/对照而非直觉 | A/B 实验、对照实验、基线对比、显著性判断 |
| 报告撰写能力 | 能给非技术读者结论 | 交付物名称（分析报告/看板/建议清单）+ 谁在用 |

## 五、JD 关键词表（提取结果，供覆盖检查）

从 JD 抽出六类词，写成一份清单（`scripts/check_resume.py --jd` 会用）：

1. **工具词**：Python、SQL、R、SAS、Spark、Tableau、Power BI、Excel 高级函数
2. **方法词**：逻辑回归、XGBoost、聚类、时间序列、A/B 检验、因果推断、抽样
3. **指标词**：AUC、KS、PSI、IV、ROI、转化率、留存率、逾期率
4. **业务词**：风控、精准营销、用户增长、供应链、经营分析、贷后管理
5. **资质词**：CET-6、CPA、CFA、FRM、软考
6. **软技能词**：沟通协调、项目推进、汇报呈现

同义词要双向认：`A/B test`＝`AB 实验`＝`A/B 实验`；`用户画像`＝`画像`；`数据看板`＝`Dashboard`。检查时人工确认命中是否**真的支撑**该要求，不要靠关键词堆砌过关。
