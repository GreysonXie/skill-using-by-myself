# ATS 可解析性与版式验收

简历有两层验收：**人眼看的版式**，和 **机器读的文本层**。网申系统读的是 PDF 里的文本，不是画面。两层都要过。

## 一、版式基线（沿用五套模板的既有视觉）

- A4 纵向，`@page margin: 11mm 14mm`；正文 13.5px，行高 1.44；标题条与线条颜色克制（一种主色 + 灰阶）。
- 模块顺序：个人信息 → 教育背景 → 项目/实习经历 → 调研或实践 → 个人荣誉 → 技能优势。空模块删掉，通常 4–6 个模块。
- 研究生在本科之上；同类经历按时间倒序。
- 学校/公司/项目名靠左，日期靠右；同一模块内对齐方式一致。
- 项目与实习合计**至少占正文三分之一版面**；项目是主要证据时，项目自身不少于三分之一。
- 加粗只加能力短语、方法名、硬指标；每条 1–3 处。
- 不新增渐变、阴影、动效、装饰符号；不改模板配色与字体层级。

内容偏少时用**真实证据补足**（多写一条方法或一条结果），不要用巨大行距、重复句、放大字号把半页纸撑满。

## 二、页数与溢出

| 情形 | 处理 |
| --- | --- |
| 初级求职、实习 | 默认**一页** |
| 有两段强相关经历（如实习 + 科研项目 + 竞赛），一页装不下 | 允许两页，但第二页至少填满 35%，不能只挂两行 |
| 第二页只剩一两行 | 回退一页：按相关性加权删减（见下） |
| 正文溢出到第三页 | 必须删内容，不要压字号、压行距、缩边距 |
| 一页但底部空 3 行以上 | 补真实内容或适度调间距，不要留半页空白 |

**相关性加权删减**（不要按模块从上往下砍）：
1. 先删重复：同一条成就在技能栏和项目里各说一次时，删技能栏那份。
2. 再删与 JD 无关的低相关条目，不管它在哪个模块。
3. 再压缩别人也能写的通用描述（"具有良好的团队协作精神"这类）。
4. 最后才动结构：合并同类条目、删最不相关的一条荣誉。

## 三、日期与状态

- 日期区间统一写 `2026.09–2028.06`，全篇只用一种分隔符；**不要在同份简历里混用 `2026.9`、`2026-09`、`2026/09`**。
- 在读学位写「（在读）」或「（预计 2028.06 毕业）」；只写区间会被读成已毕业。
- 每段经历都要有开始和结束（进行中写「至今」）。只写单一年份在部分系统里导入为空区间。
- 分隔符优先用 ASCII 连字符 `-`：部分 ATS 只按 `-` 切分区间，en dash `–` 会让起止合并或解析失败。

## 四、机器能读到的信息

必须作为**文本**出现，不能只出现在图片或图标里：

- 姓名、手机号、邮箱（邮箱前缀用真实姓名拼音，不用花名/网名/一串数字）
- 学校、专业、学位、起止时间
- 公司/项目名、岗位名、起止时间
- 技能关键词（用 JD 的原词，同义词不会自动等价）

不要出现：
- 联系方式只写在页眉图片里
- 用表格或双栏把技能与经历混排，导致文本层顺序错乱
- 生僻字/特殊符号造成的方框、`(cid:xx)`、`�`
- 用 emoji 代替小节标题

## 五、验收流程（每次导出都走）

1. 导出 PDF：`python scripts/render_pdf.py --in <HTML> --out <PDF> --paper A4`
2. 页数与文本层自检：`python scripts/check_pdf.py <PDF> --jd <JD文件>`（含页数、乱码、日期破折号、关键词覆盖、末页填充率）
3. 内容规则自检：`python scripts/check_resume.py <HTML或TXT> --jd <JD文件>`
4. 逐页看图：`python scripts/pdf_to_images.py --in <PDF> --out <目录>`，然后**真的打开看**每一页：无裁切、无重叠、无跨页断裂、项目标题不孤零零留在页底。
5. 最后用另一双眼睛：把 PDF 当成 HR，只看 8 秒，问自己三句话——我是谁、我能干什么、哪一条最打动我。答不上来就改加粗与首条。

## 六、常见故障与修法

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 项目标题在页底，条目翻页 | 分页点落在标题后 | 缩小前一段 1–2 行，或给该模块加 `break-inside: avoid` |
| 第二页只有 2 行 | 内容溢出一点点 | 删一条最低相关条目，或把两条同类合并 |
| PDF 文字复制出来是乱序 | 双栏/绝对定位 | 换单栏模板（`极简纯白`、`清新蓝灰`）后重排 |
| 文件名混乱 | 未规范命名 | `姓名-岗位-学校-手机号.pdf`，例：`谢东骏-数据分析实习-西南财经大学.pdf` |
| 打印/投递后被判排版乱 | 用了 Word 转换或截图 | 只用 HTML 直接导出 PDF，不用截图拼贴 |

## 七、多版本管理

同一份事实底稿，最多维护三个版本（见 [投放与双轨](delivery-and-tracker.md)）：

1. `通用版`：一份一页版，覆盖师门主流方向。
2. `精准版-<方向>`：针对具体 JD 重写主线与 3–5 条，文件名带公司或方向。
3. `银行/国企版`：措辞稳健、突出合规与稳定性、可含照片与籍贯。

版本之间只允许差异在**取舍与措辞**，事实必须一致。同一段经历在两个版本里给出不同数字，是面试现场最容易翻车的地方。
