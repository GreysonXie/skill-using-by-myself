# 师门简历工作室

把真实经历组织成目标岗位的**能力证据**。视觉沿用五套已验证模板，内容取舍与写作以本 skill 的规则为准；每一份交付都要过"内容规则 + PDF 文本层"两层自检。

## 任务入口

| 用户要什么 | 怎么做 |
| --- | --- |
| 新建 / 修改 / 按 JD 定制简历 | 走下面九步流程；动笔前读 [内容取舍](references/content-layout.md) 与 [中文写作规则](references/writing-rules-zh.md) |
| 判断这个岗值不值得投 | 只做 [JD 拆解与五维打分](references/jd-scoring.md)，输出门槛结论、打分与证据矩阵 |
| 不知道自己的经历该怎么写 | 按 [岗位图谱](references/field-playbook.md) 找方向，再用 [七段报告](references/experience-report.md) 提炼单段经历 |
| 排版 / 页数 / 投出去显示乱 | 读 [ATS 与版式](references/ats-and-layout.md)，跑 `scripts/check_pdf.py` |
| 投出去之后怎么办 | 读 [双轨投递与跟进](references/delivery-and-tracker.md) |
| 解释规则出处或冲突 | 读 [来源与取舍](references/source-decisions.md) |
| 只导出已有 HTML | `python scripts/render_pdf.py --in <HTML> --out <PDF> --paper A4`，再跑 `scripts/check_pdf.py`，不重新访谈或改写 |

所有相对路径以本 skill 目录为基准。模板里的示例人物、公司、数字都是样例，**不是用户事实**。

## 制作流程

**0. 建事实底稿。** 读用户已有的简历、JD、项目材料（仓库、报告、看板、笔记）。列出「已知事实 / 待核实 / 缺口」三栏，复用用户已给过的信息，不重复问。
- 标出三档可信度：用户明确确认 > 材料记载 > 待核实。只有前两档能进正式稿。
- 材料里出现的比例、客户名、上线状态，先当作待核实。

**1. 定目标与版本。** 问清或从材料推断目标方向与投递场景，选出这一份的版本：**通用版 / 精准版 / 银行国企版**（差异见 [双轨投递](references/delivery-and-tracker.md)）。
- 目标不明确时只问方向（如"数据分析 / 风控建模 / 银行数据岗"），同时并行整理事实，不要等答案才开始。
- 没有 JD 就不要假装定向：出一份通用版并在交付说明里写明"尚未针对具体 JD"。

**2. 过门槛、打分。** 按 [JD 拆解](references/jd-scoring.md) 做三道硬门槛（资格 / 语言 / 到岗）与五维打分。
- 门槛不过就直说，不为它改简历；打分 < 15 建议用通用版投，不重写。
- 打分结论用一屏能看完的表格给用户，附"最大风险"一句。

**3. 填证据矩阵。** 逐条把 JD 要求对到证据与拟放位置，缺口单列。填不出的行说明这岗暂时不该投，而不是硬凑。

**4. 访谈挖细节。** 每轮只问 1–3 个最关键的问题，给选项或例子，不让用户先写一整篇。
- 优先问：原来怎么做/卡在哪、你独立完成哪一步、结果怎么验证、团队几个人、现在到哪一阶段。
- 追问到能回答三层（事实 / 方法 / 结果），达不到的证据就降一档措辞，不升级。

**5. 出内容初稿。** 先写文字（每条一行 Markdown 即可），确认事实与取舍后再进 HTML。
- 每条按 [写作规则](references/writing-rules-zh.md)：能力短语领起、背景压缩、动作与结果为主、每条 1–2 行。
- 姓名、联系方式与一段经历足够即可开工；未确认信息留在待补清单，草稿占位必须显眼，正式稿清零。

**6. 套模板排版。** 优先沿用用户已有 HTML 样式；没有偏好时用 `极简纯白`，并说明可切换。
- 五套模板在 `assets/template_refs/html/`，同名 PDF 与预览在 `pdf/`、`images/`。
- 复制模板后替换全部示例内容，保留配色、字体层级、线条与单/双栏结构，只按内容规则重排模块与篇幅。
- 需要两页时确认第二页能填满（≥35%），否则回退一页按相关性加权删减。

**7. 导出并双层自检。** 每次都跑，不要跳：

```bash
python scripts/render_pdf.py --in out/<name>.html --out out/<name>.pdf --paper A4
python scripts/check_resume.py out/<name>.html --jd <JD文件>      # 内容规则 + JD 覆盖
python scripts/check_pdf.py out/<name>.pdf --expect-pages 1       # 页数/乱码/末页/空洞/孤立标题
python scripts/pdf_to_images.py --in out/<name>.pdf --outdir out/preview
```

- `check_resume.py` 的 HARD 必须清零；SOFT 逐条判断（有的规则可以有意违反，但要在修改说明里写原因）。
- `check_pdf.py` 的 HARD 必须清零；`thin_last_page`、`layout_hole`、`orphan_heading` 要真的看图确认。
- 然后**逐页看渲染图**：无裁切、无重叠、无乱码、无空白尾页。
- 缺依赖时如实说明，交付可编辑 HTML 与打印方法，不声称 PDF 已生成。

**8. 换一双眼睛复核。** 用两个独立视角各过一遍，不要边写边审：
- **HR 视角（8 秒）**：我是谁、我能干什么、哪条最打动我。答不上来就改首条与加粗。
- **技术面试官视角**：逐条问三层（事实 / 方法 / 结果）。答不上的表述降一档或删掉。
- 第二轮只改违反规则的句子，并保持数字、名称、工具、结论不变（可用 `check_resume.py --against 旧稿` 对比）。

**9. 交付与跟进。** 交付可编辑 HTML、可打印 PDF、简短修改说明（保留 / 前移 / 压缩了什么、为什么）与待补清单。
- 修改说明里把能力差距写成可执行的下一步，不在简历里宣称已具备。
- 用户要投递支持时，给投递记录行、跟进话术与内推推荐语（[双轨投递](references/delivery-and-tracker.md)）；不代发、不自动投递。

## 完成标准

- 每个主能力都有真实经历支撑；个人贡献、团队成果、学习复现与未完成工作区分清楚。
- 数字、日期、模型与算法名称准确；没有新增未经确认的提升比例、客户、上线或获奖事实。
- 全篇一种日期格式；在读学位写明「在读」或「预计毕业时间」。
- 正文可快速扫描：项目与角色醒目，日期清晰，每条只突出 1–3 处加粗。
- 项目/实习文字占比不少于三分之一；自我评价默认不出现。
- 技能栏是「工具 + 能完成的任务 + 支撑经历」，没有 Office 凑数、没有"精通"式空话。
- `check_resume.py` 无 HARD；`check_pdf.py` 无 HARD，页数与预期一致，文本层可复制、日期区间无 Unicode 破折号。
- PDF 逐页目视通过；双栏模板额外检查文本层阅读顺序。
- 交付物包含：HTML、PDF、修改说明、待补证据清单（投递场景再加投递记录行）。

## 边界

- 不编造经历、指标、客户、上线状态与获奖等级；不把别人的工作写成本人业绩；不把"了解/复现"写成"研发/主导"。
- 不改用户已确认的事实与日期来"美化"时间线。
- 不为了凑一页压字号、压行距、缩边距；先删内容。
- 不自动投递、不代发邮件、不代替用户与 HR 沟通。
- 模板示例人物与数字只作视觉参考。

## 脚本速查

| 脚本 | 用途 | 关键参数 |
| --- | --- | --- |
| `scripts/render_pdf.py` | HTML → PDF（Chrome headless） | `--in` `--out` `--paper A4` |
| `scripts/check_resume.py` | 内容规则自检：占位、弱开头、套话、术语、日期、占比、加粗、JD 覆盖、事实保真 | `--jd` `--against` `--max-len` `--skip-contact` `--json` `--strict` |
| `scripts/check_pdf.py` | PDF 交付自检：页数、乱码、文本层联系信息、日期破折号、JD 覆盖、末页填充、版心空洞、孤立标题 | `--jd` `--expect-pages` `--json` `--strict` |
| `scripts/pdf_page_count.py` | 只数页数 | `--in` |
| `scripts/pdf_to_images.py` | 逐页渲染 PNG 供目视检查 | `--in` `--outdir` `--pages` `--dpi` |

依赖：`pypdf`（必需）、`pymupdf`（可选，装了才有页面几何检查）；HTML 转 PDF 需要本机 Chrome/Chromium。
