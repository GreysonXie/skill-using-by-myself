# 我们的简历工作室

将真实经历组织成目标岗位的能力证据。继承 resume-master 的五套视觉模板、HTML/PDF 交付方式，以及 resumify 的七段报告格式；内容取舍与布局以本 skill 为准。

## 任务入口

- 创建、修改、针对 JD 定制：执行下面流程；先读 [内容与布局](references/content-layout.md)。
- 只提炼一段经历：读 [七段报告](references/experience-report.md)，无需制作整份简历。
- 只导出已有 HTML：运行 `python scripts/render_pdf.py --in <HTML> --out <PDF> --paper A4`，随后检查 PDF，不重新访谈或改写内容。
- 需要解释课程规则及冲突时：读 [来源与取舍](references/source-decisions.md)。

所有相对路径以本 skill 所在目录为基准。模板示例人物和数字不是用户事实。

## 制作流程

1. 读取已有简历、JD 和经历材料。列出已确认事实与缺口，复用用户已经提供的信息。没有 JD 时按用户明确的目标岗位出通用初稿，标注尚未针对具体 JD；目标也不明确时只询问目标方向，同时整理事实。
2. 拆出 JD 的准入要求、关键技能、隐性能力。建立「要求 → 用户证据 → 拟放模块 → 缺口」小表，选出 2–3 个主要能力主题。推断的隐性要求明确标注为推断；缺口放在修改说明，不写成已具备能力。
3. 按相关性、贡献深度、可核实结果挑选经历。围绕用户痛点、本人行动、方法选择、成果和完成阶段追问，每轮优先问 1–3 个最关键问题，给出选项或例子。不要让用户先写一份完整材料才开始。
4. 先形成事实可支撑的内容初稿。项目间分别证明不同能力，单个项目体现目标、方法、行动与结果。姓名、联系方式及一段经历足够时即可制作 HTML 草稿；未确认信息留在独立待补清单，草稿中的占位必须清楚标示，正式稿清除占位。
5. 优先保留用户现有 HTML 样式；已有模板选择直接沿用。没有偏好时采用极简纯白，说明可以切换。五套模板见 `assets/template_refs/html/`，同名 PDF 和预览分别在 `pdf/`、`images/`。复制模板后替换全部示例内容，保留配色、字体层级、线条及单/双栏风格，按内容规则重排模块与篇幅。
6. 完成用户要求的 HTML/PDF，不为每次导出额外设置确认门槛；用户明确要求先审稿则先交草稿。使用原有 `scripts/render_pdf.py` 导出，`scripts/pdf_page_count.py` 检查页数，`scripts/pdf_to_images.py` 按页渲染并目视检查。缺依赖时如实说明，交付可编辑 HTML 和打印方法，不声称 PDF 已生成。
7. 交付可编辑 HTML、可打印 PDF，以及简短修改理由和待核实项。只要求文字改写时交付改写文本，不强制生成全套文件。可另附面试追问；内推话术仅在用户需要时生成，不自动对外发送。

## 完成标准

- 每个主能力都有真实经历支持；个人贡献、团队成果、学习复现与未完成工作区分清楚。
- 数字、日期、模型名称和专利状态准确；没有新增未经确认的提升比例、客户、上线或获奖事实。
- 正文可快速扫描：角色与项目醒目，日期次要但清晰，每条只突出 1–3 个关键词。
- PDF 逐页确认无裁切、重叠、乱码、空白尾页；文字可选择且复制后的阅读顺序合理，双栏尤其检查。
- 初级求职默认一页；先删重复、低相关内容再调间距，必要时合理多页，避免为了凑一页牺牲可读性。
